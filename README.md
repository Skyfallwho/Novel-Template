# 小说创作通用模板

> 一套适用于长篇小说、连载小说和多模型协作的中文项目目录。复制本模板后，为每一本小说建立独立项目。

## 使用方法

1. 解压本压缩包，得到 `小说创作通用模板` 文件夹。
2. 复制整个文件夹，并将副本改名为具体小说名称，例如 `某某小说`。
3. 打开副本中的 `00-项目管理/项目简介.md`，填写作品基本信息。
4. 按需填写世界观、人物、剧情大纲等资料。暂时用不到的文件可以保留空白。
5. 正文按卷分目录，一章一个 Markdown 文件。
6. 使用 GitHub Desktop 将项目文件夹添加为本地仓库，再发布到 GitHub 私有仓库。

## 目录导航

| 目录 | 用途 |
|---|---|
| `00-项目管理` | 项目简介、写作规范、进度、待办和创作决策 |
| `01-世界观设定` | 世界规则、历史、地理、制度、势力和专有名词 |
| `02-人物档案` | 人物个人档案、关系索引和人物状态 |
| `03-剧情大纲` | 全书总纲、分卷大纲、章节细纲和剧情节点 |
| `04-正文内容` | 正式正文，一章一个文件 |
| `05-伏笔与时间线` | 伏笔追踪、事件年表、人物轨迹和连续性检查 |
| `06-资料考据` | 现实资料、来源链接、考据结论和待核实问题 |
| `07-AI协作` | AI总规则、任务交接、提示词和章节审核标准 |
| `08-出版运营` | 作品简介、平台信息、发布记录和读者反馈 |
| `09-素材资料` | 地图、图片、图表及其他创作素材 |
| `99-归档` | 废弃剧情、弃用设定和历史资料 |

## 建议的基本约定

- **一份正式资料只保留一个权威位置。** 其他文件通过链接或注明路径引用，不要复制出多个互相冲突的版本。
- **正文一章一个文件。** 文件名建议使用 `001-章节标题.md`、`002-章节标题.md` 的形式。
- **设定与正文分开。** 世界规则、人物状态和时间线应有独立记录，不要只埋在正文里。
- **重要变更写入记录。** 对人物生死、设定变更、剧情方向调整等重要决定，记录日期、原因和影响范围。
- **归档不等于删除。** 不再采用的内容移入 `99-归档`，并标记为“已弃用”，避免误当成现行设定。
- **文件名尽量稳定。** 已经被其他文件引用的文件，改名时同步更新引用路径。

## AI 阅读与协作建议

每次让 AI 执行具体任务时，按任务范围提供资料，不必默认读取整本小说：

1. `README.md`
2. `00-项目管理/写作规范.md`
3. `00-项目管理/当前进度.md`
4. 与任务直接相关的世界观和人物档案
5. 当前卷大纲、相关章节细纲
6. 必要的前文正文及 `05-伏笔与时间线` 中的相关记录

要求 AI：
- 先列出本次实际读取的文件路径。
- 区分“文件中已有事实”“本次提出的新建议”和“尚待确认的问题”。
- 不擅自覆盖既有设定；发现冲突时先指出冲突位置。
- 修改正文时保留原文件名和章节编号。
- 未经明确要求，不批量改写其他章节或设定文件。

## Markdown 文件说明

`.md` 是 Markdown 文本格式。它可以用 VS Code、Obsidian、Typora、记事本等工具编辑，也可以直接在 GitHub 网页中查看和修改。

本模板只提供目录和空白工作表，不包含任何具体小说设定。请根据作品实际情况填写。
